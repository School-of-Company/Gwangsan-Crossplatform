# ADR-0003: 채팅 전송 대기열과 재시도 설계

- 상태: 채택

## 배경

모바일 환경에서는 소켓 연결이 자주 끊깁니다(엘리베이터, 지하철, 백그라운드 전환). 소켓 `emit`은 실패를 알려주지 않기 때문에,
보낸 메시지가 서버에 저장됐는지는 서버가 돌려주는 echo로만 알 수 있습니다. 대기열 없이 보내면 다음 문제가 생깁니다.

- 연결이 끊긴 순간 보낸 메시지가 조용히 사라짐
- 재연결 후 같은 메시지가 중복 전송됨
- 끊겨 있던 동안 상대가 보낸 메시지가 화면에 보이지 않음

## 결정

### 1. 소켓 싱글턴

[`SocketManager`](../../src/shared/lib/socket.ts)가 앱 전체에서 연결 하나만 유지합니다. `auth`를 콜백으로 넘겨
재연결할 때마다 저장소의 최신 access 토큰을 읽으므로, 토큰 재발급 뒤에도 만료된 토큰으로 접속하지 않습니다.
네트워크·타임아웃으로 인한 연결 실패는 앱 버그가 아니므로 Sentry 예외 대신 breadcrumb로만 남깁니다.

### 2. 전송 대기열 (Zustand)

[`useChatQueueStore`](../../src/shared/store/useChatQueueStore.ts)는 보낸 메시지를 `tempId`와 함께 보관하고
상태를 `pending → sending → sent | failed`로 관리합니다. 이미지 메시지는 로컬 미리보기 이미지를 함께 들고 있습니다.

### 3. 전송·재시도

[`useResilientMessageSender`](../../src/entity/chat/hooks/useResilientMessageSender.ts)

- 연결돼 있으면 `sending`으로 바꾸고 emit, 연결이 없으면 `pending`으로 둡니다.
- 10초 안에 echo로 확정되지 않으면 `failed`로 바꾸고 "탭해서 재시도" 토스트를 띄웁니다.
- 연결이 `false → true`로 바뀌면 그 방의 `pending`·`failed` 메시지를 다시 보냅니다.
- Expo Router 스택은 이전 화면을 언마운트하지 않아 같은 방에 대해 이 훅이 여러 개 살아 있을 수 있습니다.
  자동 재시도를 인스턴스마다 하면 같은 메시지가 여러 번 전송되므로, **방(roomId)마다 자동 재시도 담당 인스턴스를 하나만** 둡니다.

### 4. 재연결 동기화와 echo 매칭

[`useMessageSync`](../../src/entity/chat/model/useMessageSync.ts)

- `connect` 시 채팅방 목록·현재 방 쿼리를 무효화해, 끊겨 있던 동안의 메시지를 REST로 다시 받습니다.
- echo가 오면 대기열에서 같은 메시지를 찾아 지우고 React Query 캐시에 확정 메시지를 넣습니다.
  - **내가 보낸 echo(`isMine`)만** 매칭합니다. 상대가 우연히 같은 내용을 보내도 내 대기 메시지를 지우지 않기 위해서입니다.
  - 텍스트는 내용으로, 이미지는 이미지 ID 집합으로 매칭합니다. 서버가 echo에 이미지를 채우지 않는 경우에는 같은 방의 가장 오래된
    이미지 대기 메시지와 FIFO로 매칭하고, 들고 있던 미리보기 이미지를 그대로 써서 사진이 사라져 보이지 않게 합니다.
- 지금 보고 있지 않은 방의 echo도 대기열 확정·캐시 반영은 항상 합니다.

## 결과

- 오프라인에서 보낸 메시지는 화면에 "전송 대기"로 남았다가 재연결 시 자동 전송됩니다.
- 서버가 echo를 보내지 않으면 사용자에게 실패가 드러나고, 직접 재시도할 수 있습니다.
- 대기열은 메모리(Zustand)에만 있어, 앱을 완전히 종료하면 전송되지 않은 메시지는 사라집니다. 영속화는 중복 전송 위험과 함께 별도로 검토합니다.
- 로그아웃 시 대기열을 `reset`해 다음 계정에 이전 계정의 메시지가 남지 않게 합니다.
